## 完成任务：trigger 接口 + 定时任务 + 单次运行分析

### 1. /jobs/{id}/trigger 和 /workflows/trigger 接口分析

**Job Trigger 调用链**:
```
JobResource.trigger() → JobService.trigger()
  → jobDao.selectById() [READ job]
  → groupConfigDao.selectCount() [检查组状态]
  → JobTaskConverter.toJobTaskPrepare() [转换DTO, scene=MANUAL_JOB, nextTriggerAt=now]
  → TerminalJobPrepareHandler.doHandle()
    → JobTaskBatchGenerator.generateJobTaskBatch()
      → jobTaskBatchDao.insert() [INSERT job_task_batch, status=WAITING]
      → JobTimerWheel.registerWithJob() [注册时间轮, 事务提交后执行]
        → JobTimerTask.run()
          → JobExecutorActor.doExecute()
            → ClusterJobExecutor.doExecute()
              → RequestClientActor.doExecute() → RPC 分发
```

**Workflow Trigger 调用链**:
```
WorkflowResource.trigger() → WorkflowService.trigger()
  → workflowDao.selectById() [READ workflow]
  → groupConfigDao.selectCount() [检查所有相关组状态]
  → WorkflowTaskConverter.toWorkflowTaskPrepareDTO() [scene=MANUAL_WORKFLOW, nextTriggerAt=now]
  → TerminalWorkflowPrepareHandler.doHandler()
    → WorkflowBatchGenerator.generateJobTaskBatch()
      → workflowTaskBatchDao.insert() [INSERT workflow_task_batch, status=WAITING]
      → JobTimerWheel.registerWithWorkflow()
        → WorkflowTimerTask.run()
          → WorkflowExecutorActor.doExecutor()
            → 遍历 DAG 拓扑排序
            → WorkflowExecutorFactory.getWorkflowExecutor() [按节点类型: JOB_TASK/DECISION/CALLBACK]
            → JobTaskWorkflowExecutor.execute() [每个节点创建 JobTaskBatch]
              → JobTaskBatchGenerator.generateJobTaskBatch() [INSERT job_task_batch]
              → JobExecutorActor → ClusterJobExecutor → RPC 分发
            → 节点完成: WorkflowBatchHandler.mergeAllWorkflowContext()
            → 开启下游节点: openNextNode()
```

### 2. 项目定时任务

**核心调度链 (Pekko Actor, SCHEDULE_PERIOD=30s)**:
- DispatchService → ConsumerBucketActor → 3个扫描Actor:
  - ScanJobTaskActor: 扫描 sj_job WHERE job_status=true AND next_trigger_at<=now+30s

### 3. 单次运行可行性结论

**当前代码已原生支持 "停止自动 + 手动触发" 模式**:
- Scan 扫描: WHERE job_status=true / workflow_status=true → 禁用后不会被定时扫描
- Trigger 接口: 只检查 group_status，不检查 job_status/workflow_status → 禁用后仍可手动触发
- 操作: PUT /jobs/{id}/disable → POST /jobs/{id}/trigger → PUT /jobs/{id}/enable

**关键代码证据**:
- ScanJobTaskActor.java:174 `.eq(Job::getJobStatus, true)`
- ScanWorkflowTaskActor.java:137 `.eq(Workflow::getWorkflowStatus, true)`
- JobService.trigger():176-198 不检查 jobStatus
- WorkflowService.trigger():263-288 不检查 workflowStatus
