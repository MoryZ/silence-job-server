## 核心业务实体

### 1. **Job（任务信息）**
- **表名**: `sj_job`
- **主要用途**: 定时任务配置的主实体，用于保存任务的基本信息和执行配置
- **关键字段**:
  - `groupName`: 任务所属的组
  - `jobName`: 任务名称
  - `triggerType`: 触发类型（CRON表达式或固定时间）
  - `triggerInterval`: 触发间隔
  - `executorType`: 执行器类型（Java/Python/Go等）
  - `executorInfo`: 执行器具体信息
  - `blockStrategy`: 阻塞策略（丢弃/覆盖/并行）
  - `maxRetryTimes`: 最大重试次数
  - `retryInterval`: 重试间隔（秒）
  - `argsStr`: 执行方法参数
  - `argsType`: 参数类型（text/json）
  - `jobStatus`: 任务状态（开启/关闭）
  - `nextTriggerAt`: 下次触发时间
  - `parallelNum`: 并行执行数
  - `resident`: 是否是常驻任务
  - `description`: 任务描述
  - `ownerId`: 负责人ID

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
  - 自动生成ID、审计时间戳、租户隔离
- **关联关系**: 
  - 一对多关系 → `JobTask`（任务实例）
  - 多对多关系 → `NotifyConfig`（通知告警配置）
  - 多对多关系 → `JobNotifyConfigRelation`（关联表）

**业务场景**: 创建和管理定时任务，如数据同步、报表生成、清理任务等

---

### 2. **JobTask（任务实例）**
- **表名**: `sj_job_task`
- **主要用途**: 存储Job的执行实例数据，每次调度一条记录
- **关键字段**:
  - `jobId`: 关联的Job ID
  - `taskBatchId`: 所属的调度任务批次
  - `taskName`: 任务实例名称
  - `taskStatus`: 执行状态（待执行/执行中/成功/失败等）
  - `retryCount`: 重试次数
  - `resultMessage`: 执行结果信息
  - `clientInfo`: 客户端信息
  - `argsStr`: 执行参数
  - `parentId`: 父执行器ID（用于MapReduce等复杂任务）
  - `groupName`: 组名称

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
- **关联关系**:
  - 多对一关系 → `Job`
  - 多对一关系 → `JobTaskBatch`
  - 一对多关系 → `RetryTask`（重试任务）

**业务场景**: 跟踪Job执行的每一个实例，用于调度监控和历史查询

---

### 3. **Workflow（工作流）**
- **表名**: `sj_workflow`
- **主要用途**: 支持多个Job的工作流编排，可定义复杂的任务执行流程
- **关键字段**:
  - `workflowName`: 工作流名称
  - `groupName`: 所属组
  - `triggerType`: 触发类型
  - `triggerInterval`: 触发间隔
  - `blockStrategy`: 阻塞策略
  - `workflowStatus`: 工作流状态（开启/关闭）
  - `executorTimeout`: 执行超时时间
  - `nextTriggerAt`: 下次触发时间
  - `flowInfo`: 流程信息（JSON格式，定义流程结构）
  - `wfContext`: 工作流上下文
  - `description`: 描述

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
- **关联关系**:
  - 一对多关系 → `WorkflowNode`（工作流节点）
  - 一对多关系 → `WorkflowTaskBatch`（工作流执行批次）
  - 多对多关系 → `NotifyConfig`（通知告警）

**业务场景**: 编排复杂业务流程，如数据ETL流程、订单处理流程等

---

### 4. **WorkflowNode（工作流节点）**
- **表名**: `sj_workflow_node`
- **主要用途**: 定义工作流中的单个任务节点，可关联到具体的Job
- **关键字段**:
  - `workflowId`: 关联的Workflow ID
  - `nodeId`: 节点唯一标识
  - `nodeName`: 节点名称
  - `jobId`: 关联的Job ID（可选）
  - `nodeInfo`: 节点配置信息
  - `executorId`: 执行器ID

- **继承关系**: 同上
- **关联关系**:
  - 多对一关系 → `Workflow`

**业务场景**: 构建工作流图，定义节点间的依赖关系

---

### 5. **Retry（重试数据）**
- **表名**: `sj_retry`
- **主要用途**: 存储失败任务的重试数据，支持独立的重试场景管理
- **关键字段**:
  - `groupName`: 组名称
  - `sceneName`: 重试场景名称
  - `idempotentId`: 幂等性ID
  - `bizNo`: 业务编号
  - `argsStr`: 重试参数
  - `executorName`: 执行器名称
  - `nextTriggerAt`: 下次重试时间
  - `retryCount`: 重试次数
  - `retryStatus`: 重试状态
  - `taskType`: 任务类型
  - `parentId`: 父任务ID
  - `bucketIndex`: 分桶索引

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
- **关联关系**:
  - 一对多关系 → `RetryTask`（重试任务实例）
  - 多对一关系 → `RetrySceneConfig`（重试场景配置）
  - 一对多关系 → `RetryDeadLetter`（死信队列）

**业务场景**: 处理异步任务失败的重试、补偿任务等

---

### 6. **RetryTask（重试任务）**
- **表名**: `sj_retry_task`
- **主要用途**: 重试任务的执行实例，类似JobTask但针对重试
- **关键字段**:
  - `retryId`: 关联的Retry ID
  - `taskName`: 重试任务名称
  - `taskStatus`: 执行状态
  - `retryCount`: 重试次数
  - `resultMessage`: 结果信息
  - `clientInfo`: 客户端信息

- **继承关系**: 同上
- **关联关系**:
  - 多对一关系 → `Retry`

**业务场景**: 跟踪单个重试任务的执行过程

## 配置管理实体

### 7. **GroupConfig（组配置）**

- **关键字段**:

  - `groupStatus`: 组状态（开启/关闭）
  - `groupPartition`: 分区数（用于并行处理）
  - `idGeneratorMode`: ID生成模式（号段模式/自增等）
  - `version`: 版本号（自增）
  - `initScene`: 是否初始化场景
  - `token`: 访问令牌（不可更新）
  - `description`: 描述

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
- **关联关系**:
  - 一对多关系 → `Job`
  - 一对多关系 → `Workflow`
  - 一对多关系 → `JobExecutor`

**业务场景**: 多租户或多应用隔离，定义任务分组的全局策略

- **表名**: `sj_job_executor`

- **关键字段**:
  - `groupName`: 组名称

- **继承关系**: `AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String>`
- **关联关系**:

**业务场景**: 管理多个执行器节点，支持动态路由和负载均衡

---

### 9. **RetrySceneConfig（重试场景配置）**
- **表名**: `sj_retry_scene_config`

## 实体间关系架构

### 🎯 任务执行链路
```
GroupConfig（组配置）
    ↓
Job（任务）
    ↓
JobTaskBatch（批次）
    ↓
JobTask（任务实例）
    ↓
JobLogMessage（执行日志）
```

### 🔄 工作流执行链路
```
GroupConfig
    ↓
Workflow（工作流）
    ↓
WorkflowNode（节点）
    ↓
WorkflowTaskBatch（批次）
    ↓
JobTask（节点任务实例）
```

### 🔁 重试处理链路
```
Retry（重试数据）
    ↓
RetryTask（重试任务实例）
    ↓
RetryTaskLogMessage（日志）
    ↓
RetryDeadLetter（死信队列）
```

### 📢 通知告警链路
```
NotifyConfig（通知配置）
    ├─→ NotifyRecipient（接收人）
    └─→ 关联到：Job、Workflow、RetrySceneConfig
```

### 🏢 租户隔离架构
```
Namespace（命名空间）
    ↓
GroupConfig（组配置）
    ├─→ Job
    ├─→ Workflow
    ├─→ JobExecutor
    ├─→ RetrySceneConfig
    └─→ NotifyConfig
```

### 📊 统计汇总
```
Job → JobSummary（统计数据）
Retry → RetrySummary（统计数据）
```

## 关键设计模式

### 1. **租户隔离模式**
- 通过 `Namespace` 实现最高层隔离
- 通过 `GroupConfig` 实现组级隔离
- 所有业务实体都继承 `AbstractAutoGeneratedIdAuditableTenantable`，支持多租户

### 2. **批处理模式**
- `JobTaskBatch` 和 `WorkflowTaskBatch` 支持批量调度
- `SequenceAlloc` 实现高性能ID分配

### 3. **失败重试模式**
- `Retry` 和 `RetryTask` 形成完整的重试链路
- `RetrySceneConfig` 支持多种重试场景
- `RetryDeadLetter` 处理无法恢复的失败

### 4. **通知告警模式**
- `NotifyConfig` 支持多种通知渠道
- 通过多对多关系表关联到Job、Workflow等
- `NotifyRecipient` 管理告警接收人

### 5. **分布式协调**
- `ServerNode` 管理集群节点
- `DistributedLock` 实现分布式锁

### 6. **审计日志**
- `JobLogMessage` 和 `RetryTaskLogMessage` 完整记录执行过程
- 所有实体都具备审计字段（createTime、updateTime、creator等）
