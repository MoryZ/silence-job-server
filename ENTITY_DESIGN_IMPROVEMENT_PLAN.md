# 实体类设计缺陷改进计划

## 📋 问题汇总

### 发现的设计缺陷
- **NotifyConfig.recipientIds**: 存储收件人IDs (1,2,3格式)
- **Job.notifyIds**: 存储通知配置IDs (1,2,3格式)
- **Workflow.notifyIds**: 存储通知配置IDs (1,2,3格式)
- **RetrySceneConfig.notifyIds**: 存储通知配置IDs (1,2,3格式)

### 问题的危害
1. ❌ 无法进行关联查询（如查询某个NotifyConfig被哪些Job使用）
2. ❌ 数据完整性无法保证（删除关联数据时容易出错）
3. ❌ 查询性能低下（只能用LIKE、STRING_SPLIT等低效方式）
4. ❌ 代码复杂性高（需要在应用层处理字符串解析）
5. ❌ 无法建立的数据库约束

## 🛠️ 解决方案

### 第1步：创建关联实体类

#### 1.1 JobNotifyConfigRelation（任务-通知关联）

```java
@TableName("sj_job_notify_config_relation")
public class JobNotifyConfigRelation extends AbstractAutoGeneratedIdAuditableTenantable<BigInteger, String> {

    /**
     * 任务ID
     */
    private BigInteger jobId;

    /**
     * 通知配置ID
     */
    private BigInteger notifyConfigId;

    @TableLogic
    @TableField(value = "is_deleted")
    private Boolean deleted;

    // Getters & Setters
    public BigInteger getJobId() { return jobId; }
    public void setJobId(BigInteger jobId) { this.jobId = jobId; }

    public BigInteger getNotifyConfigId() { return notifyConfigId; }
    public void setNotifyConfigId(BigInteger notifyConfigId) { this.notifyConfigId = notifyConfigId; }

    public Boolean getDeleted() { return deleted; }
    public void setDeleted(Boolean deleted) { this.deleted = deleted; }
}
```

### 第3步：Liquibase迁移脚本

```sql
-- 创建关联表：任务-通知配置
CREATE TABLE sj_job_notify_config_relation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    job_id BIGINT NOT NULL,
    notify_config_id BIGINT NOT NULL,
    tenant_id VARCHAR(50),
    created_by VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_by VARCHAR(100),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    is_deleted BOOLEAN DEFAULT FALSE,
    UNIQUE KEY uk_job_notify (job_id, notify_config_id),
    KEY idx_job_id (job_id),
    KEY idx_notify_config_id (notify_config_id)
);

-- 创建关联表：工作流-通知配置
CREATE TABLE sj_workflow_notify_config_relation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    workflow_id BIGINT NOT NULL,
    notify_config_id BIGINT NOT NULL,
    tenant_id VARCHAR(50),
    created_by VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_by VARCHAR(100),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    is_deleted BOOLEAN DEFAULT FALSE,
    UNIQUE KEY uk_workflow_notify (workflow_id, notify_config_id),
    KEY idx_workflow_id (workflow_id),
    KEY idx_notify_config_id (notify_config_id)
);

-- 创建关联表：重试场景-通知配置
CREATE TABLE sj_retry_scene_config_notify_config_relation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    retry_scene_config_id BIGINT NOT NULL,
    notify_config_id BIGINT NOT NULL,
    tenant_id VARCHAR(50),
    created_by VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_by VARCHAR(100),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    is_deleted BOOLEAN DEFAULT FALSE,
    UNIQUE KEY uk_retry_scene_notify (retry_scene_config_id, notify_config_id),
    KEY idx_retry_scene_config_id (retry_scene_config_id),
    KEY idx_notify_config_id (notify_config_id)
);

-- 创建关联表：通知配置-收件人
CREATE TABLE sj_notify_config_recipient_relation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    notify_config_id BIGINT NOT NULL,
    recipient_id BIGINT NOT NULL,

    created_by VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uk_notify_recipient (notify_config_id, recipient_id),
    KEY idx_notify_config_id (notify_config_id),
    KEY idx_recipient_id (recipient_id)
);
```

### 第4步：查询示例（改进后）

#### 获取某个Job的所有通知配置
```sql
-- 改进前（低效）
SELECT * FROM sj_notify_config WHERE FIND_IN_SET(id, '1,2,3');

-- 改进后（高效）
SELECT nc.* FROM sj_notify_config nc
JOIN sj_job_notify_config_relation jnr ON nc.id = jnr.notify_config_id
WHERE jnr.job_id = ? AND nc.is_deleted = 0 AND jnr.is_deleted = 0;
```

#### 获取某个通知配置被哪些Job使用
```sql
-- 改进后（新能力）
SELECT j.* FROM sj_job j
JOIN sj_job_notify_config_relation jnr ON j.id = jnr.job_id
WHERE jnr.notify_config_id = ? AND j.is_deleted = 0 AND jnr.is_deleted = 0;
```
